## 5. Schema & Target-Label Findings

### 5.1 Raw NDWS Dataset Schema (From Literature & Source Publications)
*Status: Partially Verified (External Academic Literature Verified; Local Raw Inspection Blocked by Absence of Files).*

The dataset is organized as TFRecord files containing serialized multi-channel feature tensors. Each record represents a $64 \times 64$ km geographic area discretized at 1 km resolution:

| Channel / Feature Key | Modality | Physical Unit | Source Sensor / Model | Mathematical Range |
| :--- | :--- | :--- | :--- | :--- |
| `elevation` | Topography | Meters | SRTM (30m aggregated to 1km) | $[0, 4500]$ m |
| `wind_direction` | Meteorology | Degrees Azimuth | GridMET Daily | $[0, 360)^\circ$ |
| `wind_speed` | Meteorology | m/s | GridMET Daily | $[0, 40]$ m/s |
| `min_temp` | Meteorology | Kelvin / $^\circ\text{C}$ | GridMET Daily | Daily minimum surface temp |
| `max_temp` | Meteorology | Kelvin / $^\circ\text{C}$ | GridMET Daily | Daily maximum surface temp |
| `humidity` | Meteorology | % / kg/kg | GridMET Daily | Specific / relative humidity |
| `precipitation` | Meteorology | mm/day | GridMET Daily | 24-hour accumulated rainfall |
| `drought` | Climatology | Index | GridMET (PDSI) | Palmer Drought Severity Index |
| `vegetation` | Biosphere | Normalized Index | VIIRS / MODIS | NDVI / EVI $[-1.0, 1.0]$ |
| `population` | Anthropogenic | Persons / $\text{km}^2$ | SEDAC GPWv4 | Human settlement density |
| `erc` | Fire Danger | Dimensionless | GridMET | Energy Release Component (fuel dryness) |
| `PrevFireMask` | Fire State ($t$) | Binary / Categorical | MODIS (MCD64A1) / VIIRS | 1 = Active/Burned at day $t$, 0 = Unburned |

#### Target Label:
* `FireMask` ($t+1$): Binary spatial grid ($64 \times 64$ pixels) indicating pixels that are actively burning or newly burned at day $t+1$.

## 7. Feature Availability & Critical Leakage Risks

### Risk 1: Temporal Satellite Overpass Asynchrony (NDWS)
* **Risk:** In NDWS, `PrevFireMask` is derived from MODIS (Terra overpass ~10:30 AM/PM, Aqua overpass ~1:30 PM/AM) or VIIRS (1:30 PM/AM), whereas meteorological variables (GridMET) represent daily aggregates (midnight-to-midnight).
* **Leakage Vector:** If a fire detection is recorded at 10:30 AM on day $t$, but `max_temp` or `wind_speed` aggregates conditions from 3:00 PM on day $t$, weather occurring *after* the morning fire observation is inadvertently leaked into day-$t$ features.
* **Mitigation Requirement:** Must document whether GridMET variables are lagged by 24 hours ($t-1$) or whether the prediction horizon strictly aligns with 24 hours post-overpass.

### Risk 2: Spatial Autocorrelation & Overlapping Patches
* **Risk:** In NDWS, multiple $64 \times 64$ km patches may be extracted from the same ongoing megafire on adjacent days or overlapping coordinates.
* **Leakage Vector:** A random row-wise train/validation/test split would place spatially contiguous patches from the same fire in both train and test sets, artificially inflating PR-AUC while failing on unseen fires.
* **Mitigation Requirement:** Event-level clustering must ensure all patches corresponding to an active incident are grouped strictly into a single split.

## 8. Target-Horizon Decisions Requiring Resolution

Before implementing the Phase 1 Machine Learning pipeline, the following 4 decisions must be resolved and documented:

1. **Point Spread vs. New Ignition Expansion:**
   * *Option A (All Active Pixels):* Label $Y_{i,j}^{t+1} = 1$ if cell $(i, j)$ is burning at $t+1$, regardless of whether it was already burning at $t$.
   * *Option B (New Spread Only):* Label $Y_{i,j}^{t+1} = 1$ only if cell $(i, j)$ was unburned at $t$ and transitions to burned at $t+1$ ($\text{PrevFireMask} = 0 \land \text{FireMask} = 1$).
   * *Recommendation:* Implement **Option B** for true spread prediction; Option A trivially rewards models for predicting persistent unextinguished fire cores.
2. **Extreme Class Imbalance Handling:**
   * In a $64 \times 64$ patch (4,096 cells), newly ignited cells frequently comprise $<1\%$ to $2\%$ of total pixels.
   * *Decision:* Standardize evaluation on PR-AUC, Recall at fixed False Positive Rates (1%, 5%, 10%), and Brier score. Prohibit reliance on overall accuracy.
3. **Tabular Feature Extraction Strategy (Phase 1 AML):**
   * How should the $64 \times 64$ raster tensor be flattened into tabular rows for XGBoost/LightGBM?
   * *Decision:* Each grid cell $(i, j)$ becomes a tabular sample with local features plus engineered spatial neighborhood context (e.g., distance to nearest burning pixel at day $t$, focal mean of windward active fire count).
4. **Missing Values & Border Nodata:**
   * Cells outside the CONUS boundary or over large water bodies contain nodata values in SRTM/GridMET.
   * *Decision:* Establish an explicit binary `valid_mask` and filter nodata cells prior to model evaluation.
