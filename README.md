# Candidate Line Breach Intelligence (CLBI)

**Research Focus:** Predictive Wildfire Containment Line Holding & Breach Intelligence  
**Core Question:** *Can predicted next-day wildfire spread provide useful directional information for identifying vulnerable segments of a proposed containment line?*  
**Benchmark Version:** `fireline_segments_v1`  

> **Evidence boundary:** This repository contains two distinct demonstrations. NDWS
> metrics are computed on the named Next Day Wildfire Spread benchmark shards. CLBI
> line-segment rows and outcomes are synthetically generated by
> [`src/data/build_dataset.py`](./src/data/build_dataset.py), using fire names as
> profile labels; they are not measured historical fireline observations. CLBI scores
> evaluate agreement with that synthetic label-generation rule and are not evidence of
> real-fire performance or operational readiness.

---

## Candidate Line Breach Intelligence (CLBI) Decision Engine

### **Problem Statement**
CLBI is an offline prototype for exploring how candidate-line features can be converted into model scores and rankings. Its included 100-meter segment records are generated examples, not observed lines or recorded breach outcomes.

### **Input Features (7 Prototype Features)**
1. `slope`: Terrain slope angle (degrees)
2. `elevation`: Surface elevation (meters)
3. `distance_to_fire`: Distance to active flame front at day $t$ (meters)
4. `barrier_width_m`: Physical cleared width of barrier (meters)
5. `burn_prob`: Generated next-day burn-probability feature $[0, 1]$ (not a live NDWS model output)
6. `attack_angle`: Acute interaction angle between line normal and spread heading (degrees)
7. `attack_dot_product`: Direct head-fire attack alignment ratio ($\cos\theta_{\text{attack}}$)

### **Output Schema**
- `breach_probability`: Predicted probability of breach $P(\text{Breach}) \in [0, 1]$
- `hold_probability`: Predicted probability of holding $1 - P(\text{Breach})$
- `risk_tier`: Prototype score band (`LOW` $<0.30$, `MEDIUM` $0.30\text{--}0.60$, `HIGH` $0.60\text{--}0.80$, `CRITICAL` $\ge 0.80$)
- `vulnerability_rank`: Ordinal ranking (1 = highest breach risk)
- `priority_percentile`: Percentile rank across candidate fireline
- `priority_recommended`: Boolean indicator for the configured top-ranked subset (not a field recommendation)
- `top_risk_factors` & `protective_factors`: Structured feature attributions
- `explanation`: Non-causal association summary

## Generated-Data Benchmark Results

The following results come from 5-fold Leave-One-Fire-Out (LOFO) evaluation on 4,600
generated segments. The target is constructed from several of the listed predictors, so
these numbers measure recovery of the synthetic rule—not performance on observed fires.

| Metric | Generated-data result |
| :--- | :--- |
| **Exp C Mean LOFO PR-AUC** | **0.9507 ± 0.0080** |
| **Exp C Mean LOFO Brier Score** | **0.1207** |

## CLBI Prototype Architecture

```
Synthetic Dataset Generation (`build_dataset.py`)
            ↓
    LOFO Pipeline Comparison
            ↓
Prototype Model Training (`train_clbi_model.py`)
            ↓
Saved Prototype Artifact (`models/clbi_logistic_regression.joblib`)
            ↓
CLBI Inference Engine (`CLBIDecisionEngine`)
            ↓
   Risk Stratification (`LOW` / `MEDIUM` / `HIGH` / `CRITICAL`)
            ↓
Exploratory Ranking and Dashboard (`/api/v1/*`, `/`)
```

### **Methodological Separation: NDWS vs CLBI**
- **NDWS:** A separate spread-prediction benchmark with metrics sourced from the NDWS result artifacts and displayed in Model Lab.
- **CLBI:** A prototype trained on generated segment data. Its held-out profile results test behavior against the synthetic target formula; they are not independent validation on historical incidents.
- **Dashboard:** The spatial grid is also illustrative and non-georeferenced. Neither dashboard workflow consumes live fire telemetry.

## Quickstart & Usage

### 1. Install Dependencies
```bash
python -m pip install -r requirements.txt
```

### 2. Generate the CLBI Prototype Dataset (Optional)
```bash
python -m src.data.build_dataset
```
The checked-in parquet dataset can be used directly; regeneration writes the CSV and
JSON versions. Generated rows are synthetic, even though their profile IDs use names
of historical fires.

### 3. Train the CLBI Prototype Artifact
```bash
python -m src.model.train_clbi_model
```

### 4. Run Unit Tests
```bash
python -m unittest discover -s tests -p "test_*.py"
```

### 5. Run the CLBI Demo & Generate JSON
```bash
python -m src.model.clbi_demo
```

## Explicit Project Limitations

1. **Synthetic CLBI Benchmark:** Five named fire profiles are used to parameterize generated feature distributions; rows and outcomes are not historical incident measurements.
2. **No Observational Validation:** CLBI evaluation measures recovery of a constructed synthetic target, not predictive accuracy on real incidents.
3. **Daily NDWS Resolution:** Input spread predictions use daily NDWS layers; cannot support sub-hourly tactical fire behavior claims.
4. **Illustrative UI Data:** The spatial grid and CLBI scenarios are generated examples; they are not georeferenced or live telemetry.
5. **Non-Causal Associations:** Model coefficients represent multivariate statistical associations, not physical causal mechanisms.
